# Proposal

## Why

`auth-client` нужна точка входа пользователя: страница с формой логина и серверный эндпоинт внутри этого же приложения, который принимает учётные данные и открывает сессию. Настоящей проверки пользователей пока нет, поэтому эндпоинт делается заглушкой, а форма, API и cookie-сессия задают контракт, на который потом встанет реальная проверка.

## What Changes

- Новая страница `/login` с формой: поля «Логин» и «Пароль» и кнопка «Войти».
- Форма отправляет из браузера `fetch` `POST /api/auth/login` с телом JSON `{ "username": string, "password": string }`.
- Новый внутренний API-маршрут `POST /api/auth/login` (resource route, без UI):
  - проверяет, что оба поля — непустые строки; иначе отвечает `400` с `{ ok: false, error }`;
  - при валидных данных **всегда считает вход успешным (заглушка)**, создаёт cookie-сессию (httpOnly) с логином пользователя и отвечает `200` `{ ok: true }`.
- После успешного ответа страница перенаправляет на `/`; при ошибке показывает сообщение на форме.
- Секрет подписи cookie берётся из переменной окружения `SESSION_SECRET`.

## Capabilities

### New Capabilities
- `user-auth`: вход пользователя — страница логина, API `POST /api/auth/login` и создание сессии.

### Modified Capabilities
- `home-page`: удаляется требование «Единственный маршрут приложения», вместо него — «Неизвестный путь возвращает 404».

## Impact

- Новые файлы: маршрут страницы логина, resource route `api/auth/login`, серверный модуль сессии.
- `app/routes.ts`: добавляются маршруты `login` и `api/auth/login`.
- Спецификация `home-page`: требование единственного маршрута заменяется требованием 404 для неизвестных путей.
- Окружение: нужна переменная `SESSION_SECRET` в production. `.env` уже есть в `.gitignore`.
- Зависимости: новых пакетов нет, сессии делаются средствами `react-router`.
- Вне рамок: реальная проверка учётных данных, выход из системы, защита маршрутов, CSRF-токены и ограничение частоты запросов.
