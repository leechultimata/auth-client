# Spec Delta

## Purpose

Позволяет пользователю войти в приложение: страница логина и внутренний API, который принимает учётные данные и создаёт сессию пользователя.

## ADDED Requirements

### Requirement: Страница входа
Приложение SHALL отдавать по пути `/login` страницу с формой: текстовое поле логина, поле пароля (ввод скрыт) и кнопка отправки.

#### Scenario: Открытие страницы входа
- **WHEN** пользователь открывает `/login`
- **THEN** страница отвечает статусом 200
- **AND** отображаются поле «Логин», поле «Пароль» с `type="password"` и кнопка «Войти»

### Requirement: Отправка формы во внутренний API
При отправке форма SHALL выполнить `POST /api/auth/login` с телом JSON `{ "username", "password" }` и заголовком `Content-Type: application/json`, не перезагружая страницу.

#### Scenario: Отправка заполненной формы
- **WHEN** пользователь вводит логин и пароль и нажимает «Войти»
- **THEN** браузер отправляет `POST /api/auth/login` с JSON-телом, содержащим введённые значения
- **AND** кнопка отправки недоступна, пока запрос выполняется

### Requirement: Валидация запроса входа
`POST /api/auth/login` SHALL отвечать `400` с JSON `{ "ok": false, "error": string }`, если тело не является JSON или если `username` либо `password` отсутствует или пустой после обрезки пробелов. Сессия при этом SHALL NOT создаваться.

#### Scenario: Пустой пароль
- **WHEN** клиент отправляет `{ "username": "alice", "password": "" }`
- **THEN** ответ — `400` с `ok: false`
- **AND** в ответе нет заголовка `Set-Cookie`

#### Scenario: Некорректный JSON
- **WHEN** клиент отправляет тело, которое не является JSON
- **THEN** ответ — `400` с `ok: false`

### Requirement: Успешный вход (заглушка)
При валидном теле `POST /api/auth/login` SHALL считать вход успешным без проверки пароля, установить httpOnly cookie сессии с логином пользователя и ответить `200` с JSON `{ "ok": true }`.

#### Scenario: Валидные данные
- **WHEN** клиент отправляет `{ "username": "alice", "password": "secret" }`
- **THEN** ответ — `200` с `{ "ok": true }`
- **AND** ответ содержит `Set-Cookie` с атрибутами `HttpOnly`, `Path=/` и `SameSite=Lax`

#### Scenario: Cookie защищена в production
- **WHEN** приложение запущено в production
- **THEN** cookie сессии устанавливается с атрибутом `Secure`

### Requirement: Неподдерживаемые методы API
`/api/auth/login` SHALL принимать только `POST`; на `GET` эндпоинт SHALL NOT отдавать HTML-страницу и SHALL отвечать `405`.

#### Scenario: GET-запрос
- **WHEN** клиент выполняет `GET /api/auth/login`
- **THEN** ответ — `405`

### Requirement: Результат входа на странице
После ответа API страница входа SHALL перенаправить пользователя на `/`, если `ok: true`, а иначе показать текст ошибки на форме, оставив введённый логин.

#### Scenario: Успех
- **WHEN** API отвечает `200` `{ "ok": true }`
- **THEN** пользователь оказывается на `/`

#### Scenario: Ошибка
- **WHEN** API отвечает с `ok: false` или запрос не удался из-за сети
- **THEN** на форме отображается сообщение об ошибке, а поле логина сохраняет значение
